# Page Recipe

[English](README.md) · [日本語サイト](https://pdf.optmodel.com/ja/)

ブラウザー内でPDFのページ順を計画し、実際のPDFを出力します。元資料の別名、逆順範囲、意図的な重複を含むレシピを保存・再読込できます。

## 導入と実行

Node 24以降とnpmが必要です。依存関係の取得時には通信します。

```sh
git clone https://github.com/kolmo2026/page-recipe.git
cd page-recipe
npm ci
npm run build
npm run serve -- --port 4173
```

サーバー起動後にhttp://127.0.0.1:4173を開きます。停止はCtrl+Cです。

## 再現できる例

**入力：** examples/paper.pdf（A、5ページ）とexamples/supplement.pdf（B、2ページ）を選択します。レシピ：A:1-3,B:2,A:5。

**出力：** 新しい5ページのPDF：A1、A2、A3、B2、A5。A:5-3,A:1,A:1ならA5、A4、A3、A1、A1になります。入力バイト列は変更しません。

サンプル：examples/paper.pdf, examples/supplement.pdf and examples/recipe.json (generated by npm run build)。同梱文書と数値はすべて合成例です。

## テストとビルド

```sh
npm test
npm run build
```

サイトの編集元は`site/`、生成手順は`scripts/`です。ツール実装は`src/`、核となるテストは`test/`にあります（blogには計算エンジンはありません）。独立した静的サイトを`docs/`に生成し、英日対応ページ、canonical/hreflang、sitemap、robots、CNAME、.nojekyllを含めます。公開用ホストはhttps://pdf.optmodel.comです。隣のリポジトリに依存せず単独でビルドできます。

## 制約

通常の非暗号化PDF向けです。署名、しおり、添付、フォーム、ページラベル、文書メタデータの保持は前提にできません。OCR、墨消し、修復、規格検証は行いません。ページは印刷番号でなく1始まりの物理位置です。レシピ上限は1万ページですが、メモリー制約はそれより厳しい場合があります。JSONは名前とページ数のみ照合し、内容の同一性は保証しません。原本を上書きせず別名保存してください。一部エラー文は英語です。

## プライバシーと関連製品

アカウント、アクセス解析、バックエンド、文書のアップロード先はありません。計算とファイル処理はローカルです。ただし公開サイト資源の取得には通信します。ブラウザー依存ライブラリーは同梱し、実行時CDNは使いません。JSONは平文なので、共有前にファイル名や条件を確認してください。

[KomoPDF](https://komopdf.com/)：関連するPDF編集・注釈製品で、このページコピーツールとは別です。

GitHubアカウント**kolmo2026**を通じて、Eqvero・KolmoPDF・KomoPDF向けツールを開発する同じ保守チームが管理しています。独立した第三者レビューや推薦ではありません。KolmoPDFのクラウド処理は文書をアップロードする別サービスです。
